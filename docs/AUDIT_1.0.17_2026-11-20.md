# GoConnect 1.0.17 网络审查复核

复核基线为正式 tag `v1.0.17`，源码提交 `28170362967f567018f4f2dcd551724a0a1e092b`。Antigravity 的报告覆盖 12 项。以下结论根据该提交的源码、以往验收和本轮回归整理。

| 项 | 复核结论与 1.0.18 处置 |
| --- | --- |
| 1. 多网卡巡检 | **确认并修复**。旧实现启动时读取系统默认路由，运行中按网卡枚举顺序选第一个带 scoped default 的接口。双网卡回归复现了假切网。现在以系统默认路由为准，并处理 IPv6-only 环境中查表返回本次自有捕获路由的情况。 |
| 2. 恢复触发与探测 | **部分确认并修复**。旧版可漏掉同一物理网卡上 VPN 外层 IPv6 原生网关更换。看到明确的新原生网关后走同线路恢复。相同网关下隧道假死仍需现场判断，探测失败用于显示「线路降级」。 |
| 3. 固定 DoH | 两个固定上游已互为备选。两家均不可达时保持失败保护。新增上游或配置入口会影响解析信任关系，需要单独验证。 |
| 4. 网络快照 | 原网络 DNS、LAN 和 Tailscale 规则在连接启动时读取。macOS 的更具体路由仍可直接工作。新增 DNS 作用域或需进 TUN 的新网络可能需要重连，动态刷新仍待设计。 |
| 5. 名单地址复核 | 命中二次 IP 匹配后确实固定已检查的地址，防止重新解析后跨越已判定的规则。公司或业务 CDN 的普遍异常缺少实测依据。 |
| 6. 全局排除 App 的 DNS | 报告描述符合现行策略。全局排除 App 的连接走原网络，系统默认公网 DNS 仍走代理 DoH。按 App 的公网 DNS 分路需要独立验证共享解析器、域名策略和浏览器兼容。 |
| 7. Fake-IP 和 IPv6 | **现场确认并修复误拦**。切换测试版时，Tailscale 的 scoped default 给保留映射网关留下了一个克隆主机条目。候选只豁免匹配接口及链路的这类缓存条目，保留真实冲突拦截。名单公网合成 AAAA 被抑制，用于避免浏览器本地网络权限弹窗。原生补充域仍可返回真实 AAAA；旧映射在 App 自己的缓存中可能短时保留。 |
| 8. 订阅外层地址 | 确认只选一个地址并为它固定绕行路由。多入口故障切换还需处理认证、SNI 和地址更换时的路由所有权。 |
| 9. TUN、签名和嗅探 | 报告列出的路径与嗅探设置存在。本地更具体路由可以绕过 TUN，签名和解释器边界用于约束包外 Helper 归属。吞吐和首包影响缺少现场度量。 |
| 10. 公司 DNS | **确认并修复两项**。公司域追加到名单模式的 Fake-IP 过滤。运行期首选公司 DNS 不可用时，在总时限内尝试现有公司备用 DNS。负答复或超出公司域名／网段范围的答复继续结束本次查询。公司副线的 IPv4/TCP 范围和关闭时阻断继续生效。 |
| 11. AnyConnect 桥接 | 共用发送协程可能受 socket 背压影响，队列有容量上限。历史 UDP 偶发超时按已确认的非阻断范围处理，TCP 性能影响留待现场采样。 |
| 12. 会话状态与隔离 | **确认并修复状态发布**。先生成完整私有快照，再原子替换状态文件。读者可读完旧快照，新读者收到最终失败原因。路由归属不明时的隔离按原保护流程处理。 |

## 回归验证

- 旧版在模拟系统主网卡仍有效、另一网卡拥有 scoped default 时报告了误切网。新代码保留主网卡，有真实网络变化证据时仍按原流程恢复。覆盖 IPv6-only、自有捕获路由、其它 VPN 冲突、IPv6 网关轮换和清理失败。
- 旧版 DNS 首选返回 EOF 或 SERVFAIL 后直接失败。新增对照覆盖公司备用服务器、首选无响应、有效负答复和超范围返回。真实打包内核用隔离公司后端验证公司 A 记录、无关域名的 Fake-IP 映射和公司链路断开后的拒绝。
- 保存旧状态读取句柄后发布终态。旧代码让该读取者看到被覆写的终态；新实现同时保留旧句柄的数据和新路径的完整终态。
