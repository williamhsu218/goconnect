## 覆盖与优先级

1. 保留已有的域名、IP、LAN、Tailscale 和公司范围优先级。
2. 显式直连路径与独立可执行文件精确匹配优先；已保存的 CLI 固定入口继续在连接时解析，未改成整个目录或进程名放行。
3. App 包内进程仍按原 App 路径匹配。包外 Helper / 内置 CLI 由 `GOCONNECT-APP-CHILD` 核实本次进程实例的启动链：实际套接字 PID、同一会话 UID、最多 12 层仍存活父子关系、启动时间、执行映像、有效 Apple 锚定签名及 CDHash，并在判定结束复核。
4. 包外代码须与 App 链上的已验证签名团队一致，或是 App 专属 Application Support / Caches 目录中的有效签名程序。终端、共享 Shell/解释器、其他 App 边界、跨 UID、未知或失效身份均不继承。没有全局 PID/路径授权缓存，不扩大到独立启动的同一 CLI 文件。
5. 名单模式关联 App 的包外进程后，继续选择相同代理 DNS/地址重匹配出口；全局模式中被排除 App 的相关包外进程继承直连数据路径，公网系统 DNS 保持既有全局语义。两种模式默认出口不改。

明确的直连 App / CLI 现在通过临时 RouteSession 的 `directAppPaths` 传给新服务，防止派生关联覆盖用户排除项。缺失的可选直连 App 不阻止连接，仍保留其合法原路径；可用 CLI 别名解析为精确实际文件。没有改写保存的用户配置或增加持久名单记录。

## 边界

无法核实的 launchd/XPC/已脱离父链进程、无有效签名的包外代码，以及经共享 Shell/解释器转交的进程不自动继承，保留相应模式原有默认规则；可以继续使用现有独立 CLI/服务配置。它不是任意子进程、所有脚本或任意第三方程序的自动代理授权，也不将整个签名团队、UID、Terminal、node、Python 或目录加入名单。

新连接逐次验证；已建立连接保持建立时的出口。当前独立 CLI 的升级路径仍按既有连接时解析方式处理，连接期间更换其真实执行路径仍需正常重连。此处没有加入通用的独立 CLI 热更新或改变系统共享进程的归属机制。
