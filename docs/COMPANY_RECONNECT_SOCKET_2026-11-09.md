# 公司副连接再次连接被本地 socket 拒绝（2026-11-09）

## 现场定位与恢复

安装版为 1.0.11 / build 71。用户断开并重新建立主线路后，公司副线一次完成认证及 ready，停止后再次连接立即显示“请检查服务器地址和账号信息。”。第二次没有启动 OpenConnect，提示来自 `request.validate()`，不是服务器返回的账号或密码错误。

主线路控制目录仍为 ready，公司出口保持 blocked，但 `company.sock` 文件残留。该文件为当前用户所有的 0600 UNIX socket，父目录为规范路径及当前用户所有的 0700 目录；连接返回 ECONNREFUSED，未发现持有该 socket 的进程，公司 OpenConnect 及 hook 已退出。占用路径触发了已有的安全校验。

仅将这个确认为失效、身份未变化的 socket 移入废纸篓，没有删除控制目录、lease 或主线路运行文件。用户重新在本机输入密码后确认连接成功；只读复查确认公司出口 active、公司系统 DNS 返回预期地址、内网接口 HTTP 200、公网 HTTP 204，主线路各进程身份及三份配置哈希与处理前一致。

## 源码修正

OpenConnect 组长退出后，`stopChild` 会结束仍在运行的所属 hook 进程组；hook 可能在执行 listener 的 defer/unlink 前被 SIGKILL。因此 session 现在承担进程组退出后的最终 socket 清理：

- 结束所属进程组之前记录 socket 和私有父目录的文件身份，保留原目录描述符。
- 只有 `stopChild` 确认整个所属组退出后才继续；退出未确认时保留 socket。
- 再次校验规范路径、父目录身份、所有者、权限、socket 身份，并通过短时本地连接确认 ECONNREFUSED；仍有监听器、文件被替换或权限改变时拒绝移除。
- 通过原目录描述符只 unlink 该 socket，不修改主线 lease、路由、DNS、认证信息或其他文件。hook 或主控制器已清理时正常完成。
- 路径占用有独立本地错误提示，不再显示为账号信息错误。普通非公司连接继续走原有停止流程。

回归覆盖重复四次后端连接与退出、进程组退出未确认、活跃监听器、替换成普通文件/socket/符号链接、原目录被替换、目录权限变化、正常提前移除、退出过程中才出现未知 socket，以及原有非公司连接。
