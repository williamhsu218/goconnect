# 公司副连接：已完成请求未释放连接名额

日期：2026-11-07。起点为正式版 1.0.10 / build 70；本记录不表示已发布或已安装修复。

## 现象与定位

用户报告从工作台切换到“历史账本”时超时，随后同一内网主机的其他服务也可能无法访问。页面偶尔恢复，单次健康检查可以成功，因此此前的可达性检查不能作为稳定性验收。

只读检查发现公司桥接进程保留约 250 个 UNIX socket 描述符，接近每层 SOCKS 服务的 256 个并发连接上限；继续观察仍有累积。描述符数量仅作运行线索，不等同于对每条连接状态的完整证明。没有通过重连或改写配置来重现问题。

隔离回归测试使用两层生产 SOCKS 包装、真实回环 TCP/UNIX socket 以及合成响应，不访问公司网络，不建立系统 TUN，不修改路由或 DNS。旧代码在第 257 个顺序短请求上失败，确认已完成请求仍占用连接名额；请求半关闭后等待响应的场景也超时。

## 原因与修改

- `companySOCKSConn` 的协议过滤包装隐藏了底层 socket 的 `CloseWrite`。
- `companyFlow` 的跟踪包装也隐藏了 `CloseWrite`。
- `x/net/proxy` 的 `DialContext` 返回额外的代理包装，同样没有暴露底层 UNIX socket 的半关闭。

通用 SOCKS 转发有意等候双向复制结束，以保留请求半关闭后才到达的响应。半关闭无法传递时，另一侧持续等待 EOF，两层转发不能完整退出并归还名额；并发上限耗尽后，新建公司 TCP 请求失败。独立测试还确认，服务器已关闭连接时，客户端虽收到完整响应内容，仍不能收到 EOF。这为浏览器复用失效连接时的挂起提供了传输层解释，但不等同于已捕获每一次原页面故障的完整计时。

修复使公司包装转发 `CloseWrite`，并在经过原有 UID/PID/启动时间/代码身份验证的 UNIX socket 上执行相同的 SOCKS 认证握手，保留原始连接。握手仍受 context 的取消与超时约束，失败即关闭 socket。没有新增系统网络回退，也没有改变公司范围、身份验证、并发上限或现有阻断策略。

## 验证边界

新增 `company_half_close_test.go`，覆盖：

1. 顺序 300 个短请求超过原有 256 上限，全部成功，结束后公司流数量归零。
2. 客户端结束发送后仍完整接收 400,000 字节延迟响应，随后释放流。
3. 服务器关闭连接的 EOF 对客户端可见，不再保留表面可复用的失效连接。
4. 同一长连接复用 10 次请求，正常结束后释放流。

旧代码以上四项均失败，修复后均通过；最终四项均使用 Go race 检查。服务器 EOF 的旧版复现使用临时源码 overlay，未回写工作区或影响已运行组件。

`./script/build_and_run.sh --verify` 完整通过：39 项 Python 测试、193 项 Swift 测试、Go race 检查、应用与运行组件构建及包校验、随包网络集成测试（127.392 秒）均成功。公司 CSTP/TCP、UNIX 后端身份、UDP 拒绝与 EOF 清理检查通过；需要实际安装服务的系统 TUN 测试按显式门禁跳过，不宣称已完成真实公司线路稳定性验收。完整脚本耗时 239.8 秒，临时构建目录已自动清除。

本轮未替换正在运行的应用、未升级正式服务、未重连主副 VPN，未修改用户配置或服务器数据。现有安装版不会因源码修复自动生效；修复同时涉及主连接内的公司路由控制与用户侧公司桥接，须在可中断窗口通过正常流程升级网络服务、重建连接后另行实机验收。没有发布新版本，也没有提升生产更新源。

原始回归日志与脱敏运行证据保存在项目外的私有诊断目录，不随仓库公开。

## 正式放行前补验：取消与无响应上游

后续协作审查提出客户端取消与连接重置的边界。新增双层回环测试确认：普通 HTTP 后端随请求取消而退出时可回收；但客户端 RST 后，故意不退出的上游会继续占用两层名额。只在复制错误时关闭两端可释放根端，却会在后端留下一个 UNIX socket；因此不能只观察根端 flow map 就判断已经回收。

公司两层转发现在显式启用独立的 75 秒半关闭空闲排空策略：复制出错时立即关闭两端；正常 EOF 继续传递 CloseWrite 并等待响应，但无成功转发进度达到空闲界限时回收。计时使用单调时钟，成功写入刷新进度，活跃响应不受固定总时长限制；两向仍打开的长连接不会启动该计时。默认零值保留原有转发，因此主线路 TCP 与 UDP 行为不变。公司策略常量与外层传输重连预算分开命名，避免未来修改互相影响。

补充验证直接检查隔离测试进程的 UNIX 描述符，包含已失去 peer 的 accepted socket，避免只数仍然连接的 socket 漏掉孤儿。重置、根上下文取消、公司世代撤销、服务端先 EOF、正常 FIN、默认零值与持续慢响应均已覆盖；重点取消及计时场景使用 race 重复 10 次通过。最终完整签名包与真实线路状态仍以本版本发布记录为准。
