# GoConnect 1.0.15（build 75）

修复按名单代理与全局模式下的流量规则边界，并加强更新安装前的真实服务空闲核验。

- 名单模式先按应用选择代理或原网络 DNS，再用同一真实地址匹配直连 CIDR、LAN 和主线路网段，避免域名访问漏匹配；连接时固定匹配地址，避免二次解析改变出口。保留全局代理 DoH、明确直连域名与原生专用解析域。
- 同一 UDP socket 访问不同目标时分别匹配出口；公司域名和网段明确拒绝 UDP，避免 TCP-only 公司出口被跳过后回落主线。公司副连接仍限明确 IPv4/TCP。
- 公司域名冲突检查区分精确域名与后缀域名，允许互不重叠的精确父域名；真正重叠仍拒绝。
- 保留有效原生 search 域，增加名单 fake-IP 地址池与接口、路由、网关及 DNS 的启动前冲突检查，失败时不改系统网络。
- 更新安装前等待并重新核对网络服务实际空闲；超时、读取失败或取消时阻止交接并释放新连接门禁。检查与下载仍可使用当前 VPN。
- 直连地址支持文本文件导入/导出与预览确认，合并和替换分别选择；普通查看或取消不改变配置。

更新后请在“诊断”页按提示升级网络服务，再正常重连。保存线路草稿，确认安装重启后才正常断开；自动检查默认关闭，下载与安装由用户确认。

本版使用固定源码和补丁哈希的 Mihomo v1.19.30-goconnect1，附匹配的第三方源码与构建材料。适用的签名、隔离 OTA、安装及两种模式/公司副线验收结果记录在 docs/PUBLISH_1.0.15_2026-11-10.md；没有将隔离测试代替真实 TUN 验收。

仅接受原始 AAAA 而不接受 IPv4 映射的专用客户端在名单延迟解析区域仍有限制。包外 helper、应用自带 DoH、独立 DNS 和未知进程遵循各自边界，不承诺任意 AI 客户端零泄漏。仅填 IP 网段不能推断未知公司域名的 DNS 范围。历史 AnyConnect UDP 偶发超时仍为已接受的非阻断限制，未重做该实链路稳定性验收。

适用于 Apple Silicon / macOS 26.0 及以上。沿用团队 RX44JC39GB 的 Apple Development + Hardened Runtime，未采用 Developer ID 分发签名，未经过 Apple 公证；应用 ZIP 与完整更新源继续使用既有 Ed25519 签名、公钥及固定生产地址。
