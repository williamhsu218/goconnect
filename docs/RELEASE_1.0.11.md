# GoConnect 1.0.11（build 71）

修复公司副连接的 TCP 连接回收问题：请求结束后，原先有部分连接未释放，逐渐占满 256 个并发名额，导致公司网页、数据接口或其他内网端口超时。服务器关闭连接的通知现在能够传到客户端，避免浏览器继续复用已经失效的连接；同时保留正常长连接，以及请求结束后继续返回响应的能力。

补齐取消请求的清理：公司连接发生传输错误时关闭两端；正常半关闭后若连续 75 秒没有成功转发数据，回收残留连接。持续有进度的响应会刷新空闲计时，正常保持打开的长连接不设这个空闲期限。该策略仅用于公司通道两层转发，主线路与 UDP 路径不变。

公司副连接作为可选正式功能提供，移除界面中的“试用”标记。入口仍默认隐藏，需要时从 **设置 → 高级功能 → 公司副连接** 配置开启；已有网段、公司域名、DNS、主副线路关联与启用状态继续保留。

本次修复不扩大公司网络范围：公司业务限明确批准的 IPv4 私网与 TCP，域名及其子域名的解析结果仍须位于批准网段内；公司 DNS 可从服务器获取。公司线路未连接时，已保留的公司地址继续阻断，不转交公网主线路。局域网和已有规则冲突时仍拒绝启用。

## 更新与使用

1. 可保持 VPN 检查、下载及验签；由用户确认最终安装。
2. **本版需要更新网络服务并重新建立主、副连接。** 请在可短暂中断网络的窗口中安装，在诊断页按正常流程升级服务，然后连接原有主线路及公司线路。只重载网页不能修复旧组件中的残留连接。
3. 公司密码仅在本机输入。不需要公司网络的用户无需开启此功能。

隔离回归覆盖 300 个顺序短请求的名额回收、400,000 字节延迟响应、服务器关闭通知、长连接复用、客户端重置、取消、公司会话撤销，以及持续慢响应的空闲计时刷新；相关计时与取消用例重复 10 次通过 Go race 检查。真实线路、最终签名包、完整构建及 OTA 放行结果见本版本发布记录；隔离测试不代替真实线路验收。

当前功能范围不包含 AnyConnect UDP 和 Finder 内核 SMB；睡眠恢复及不同企业环境仍需要针对性验证。历史 AnyConnect UDP 限制未修复、未重新验收。

适用于 Apple Silicon / macOS 26.0 及以上。沿用团队 RX44JC39GB 的 Apple Development 签名和 Hardened Runtime，不是 Developer ID 分发签名，未经过 Apple 公证。应用 ZIP 与完整更新 feed 分别经原有 Ed25519 信任链签名；Bundle ID、公钥、账户及固定生产源不变。
