# 系统 DNS 接管与分流

1.0.8 在透明分流连接中增加系统 DNS 接管。1.0.7 的 HY2 节点内 DNS 转 DoH 保留；系统查询不再依赖它是否先进入节点。

## 路径和边界

- 系统默认解析经本机仅回环监听的 TCP/UDP DNS 入口，再经本次连接的认证 SOCKS 发送 Cloudflare/Google DoH。公网域名默认使用此路径，包括未设为直连的 OpenAI、Anthropic、Gemini 域名；无直连 fallback，TLS 正常校验，HTTP/3 关闭。
- DNS 例外复用用户已有直连域名，保留精确域名与含子域名的区别，不自动扩充网站直连规则。国内直连域名用连接前的原解析器，避免海外解析改变 CDN 调度；应用和网站流量的既有分流规则不变。
- 单标签主机名、local/lan/home.arpa/internal、反向域名保留原解析。已存在的 macOS 更具体域名解析器继续由系统优先匹配；内核收到相应查询时保留原服务器、端口和接口。Tailscale/局域网路由不改。
- 只接管系统默认 DNS；不拦截所有私网端口 53 请求，不强制改写应用自带的 DoH/DoT。自带解析和指定网卡的应用仍须按其实际连接路径检查，不能宣称整机所有应用零泄漏。用户明确设置的 DNS 直连例外仍为直连。
- 不新增企业 VPN 下发内部 DNS 的能力。现有专用解析器可保留，但未配置的企业域名不会自动获得公司解析器。

## 生命周期和故障

特权 worker 先读取系统 DNS 快照，生成明确的原解析器地址和接口。接管后的配置不调用 `system`，避免把原解析回流到自身。节点网关在接管前已解析为 IP，代理建立不依赖新的默认解析器。

内核需先通过本地 TCP/UDP DNS 回应验证，再通过 SystemConfiguration 的 `SCDynamicStoreAddTemporaryValue` 注册独立临时 DNS 服务，并读回系统实际采用的解析器。该操作不改写系统网络偏好，不保存旧偏好后覆盖恢复。正常退出撤销本次独立记录后才停止内核；worker 被强制终止时由 configd 自动删除其临时记录。

连接健康检查覆盖 DNS 监听和临时记录的所有权。安装或监听失败不得报告连接成功；保护失效则按现有停止流程恢复网络。断开后恢复原网络解析，不是断线后的全局网络封锁功能。DNS 快照随重新连接更新。

## 验证

- 单元/真实内核：默认公网、精确/子域名直连、IPv6 链路本地 zone、专用接口/端口、单标签/私有域名；代理解析失败时无本地 fallback，国内查询仍可用。
- 生命周期：正常断开、租约撤销、连接启动失败、核心退出、路由失败、DNS 注册失败/所有权改变/监听失败与清理顺序。
- 原生隔离：临时随机域名经 macOS 原生查找进入测试 DNS，正常结束和 SIGKILL 后系统记录消失。
- 实链路：候选解析器通过当前既有节点，短时注册系统默认 DNS；AI 和国内查询成功，权威 DNS 观测区分原解析器和代理解析器；人为令单个测试域名的 DoH 失败后无系统直连重试。测试后 DNS 完整恢复，正式 App/VPN 保持原进程，用户配置不变。

原始证据留在项目外私有目录；发布构建、完整回归和 OTA 等结果以对应发布验收记录为准。上述证据不代表全部企业网络、自带加密 DNS 的应用或 WebRTC 已验收。
