## 本轮验收设计

三条路径并行请求：透明 VPN、显式 SOCKS VPN，以及绑定物理出口 en0 的直连对照。UDP 使用相同 STUN 端点，单次发送、15 秒期限，不因重试掩盖丢失；HTTPS 保持 20 秒期限。直连 HTTPS 使用不同的可达站点，只有可用性对照含义。

测试 UDP 事务带匿名标记，以本机私有桥接日志逐笔核对九个环节；日志丢弃、序号缺口和覆盖不足必须单列，不能当作报文丢失证据。基线已验证日志权限 0600、实际 bridge PID 和完整往返记录。

计划双路 4K / 30 fps / libx264 medium / 每路 8 线程持续 840 秒，探针持续 900 秒。前 600 秒纯渲染，不注入故障；随后在相同负载下暂停 OpenConnect 8 秒、原生重连、暂停 App 8 秒、再次原生重连。暂停具有 finally 恢复；不退出原会话或改路由配置。明确区分主动暂停产生的延迟与此前自发的 UDP 超时。

## 桥接证据与根因边界

432 个 VPN UDP 测试事务均有九阶段记录，日志序号连续，bridge / App 丢弃计数为零。SOCKS 收到请求到完成 packet socket 写入，中位数 0.123 毫秒、最大 10.005 毫秒；packet socket 写入调用本身最大 0.291 毫秒；读回后到 SOCKS 回复最大 1.199 毫秒。暂停 OpenConnect 时，标记报文在交付 packet socket 后等待读回约 8.09 秒，恢复后完整返回，没有触发会话清理。

已确认并修复的本机缺陷是：UDP 写失败后旧代码仍可能缓存失效目标连接。隔离用例先在旧代码失败，再在修复代码通过，部分写入不重放、下一请求恢复、取消可中断；详见前一份桥接报告。本轮真实测试没有再次出现 UDP 超时，也没有触发该写失败分支。因此可以确认修复有效且本次实际验收通过，**不能倒推所有历史 UDP 超时都由该缺陷导致**。

验收范围是本机、当前 VPN、两个测试端点、有限高负载及受控恢复场景；不承诺任意系统冻结、任意网络条件或无限时长零丢包。75 秒恢复硬上限、30 秒租约 / 健康窗口、认证 / 证书拒绝、核心退出、用户取消、真实换网等保护仍保留。0.11.13 构建的 73 项 Swift、Go race、打包恢复与保护测试已通过；认证拒绝和长时间无恢复场景在隔离环境验证，没有对公司 VPN 制造认证失败。
