# HY2 会话统计与公网出口 IP · 2026-10-31

## 问题与实现

旧版订阅会话只发送 `ready`，没有流量事件，且地址数组为空。连接卡片因此始终显示 0 B 与“分配中”。

- 订阅节点的普通用户 Mihomo 内核现在启用带随机会话密钥的回环控制接口。每秒读取 `/connections` 的 `downloadTotal` / `uploadTotal`，发布累计收发事件。该接口的累计值口径见 [Mihomo 官方 API 文档](https://wiki.metacubex.one/api/#connections)。采集对象是只承载所选代理的节点内核，避免把系统分流内核的直连流量算入线路统计。
- `SessionTrafficMeter` 在样本到达时计算速率，独立于窗口可见性与界面定时器。读取失败或样本过期显示待更新，保留最后累计值；恢复、计数器回退及新会话不产生巨大速率尖峰。
- HY2 等订阅代理线路显示“虚拟地址：不适用 / 代理线路不分配隧道地址”。AnyConnect 继续显示实际收到的虚拟地址，未上报时明确标记，不将它当成公网 IP。
- 新增“公网出口 IP”与刷新操作。探测使用当前会话经过认证的 SOCKS 入口，HTTPS 校验证书，不受系统代理环境变量或直连域名例外影响；失败不会回退直连。支持 IPv4 / IPv6，拒绝本地、私有、保留地址及无效响应。
- 出口探测使用固定的 `api64.ipify.org` / `api.ipify.org` HTTPS 服务，最长约 13 秒；界面区分检测中、成功时间、失败与未连接。断开、重连和新一轮探测取消旧任务并丢弃旧结果。
- 节点诊断会话也可以查看同一统计卡片；“诊断进行中”不表示已启用系统分流。
