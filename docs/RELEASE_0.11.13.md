## 修复内容与归因

- **本机查询与租约误超时**：后台独立续约，已连接阶段的只读健康查询使用有界容错窗口，避免短时调度延迟立即清理 VPN。原两次断线的直接触发分别是路由查询超时和租约过期，见[原始诊断](INCIDENT_2026-10-17_RENDER_LOAD.md)及[超时修复](LOAD_TIMEOUT_FIX_2026-10-18.md)。
- **分层恢复与背压**：保留会话和原有本地转发通道，通过 OpenConnect 原生重试恢复短时断流；本地报文写入处理暂时背压。保留 30 秒租约 / 健康窗口、60 秒原生重试预算、75 秒恢复硬上限，以及认证、证书、核心退出、取消、真实换网和路由异常保护。见[分层恢复记录](LAYERED_RECOVERY_2026-10-18.md)。
- **高负载下服务调度**：特权网络服务从 Background 改为 Interactive，解决已观测到的低优先级调度问题；对照支持其对延迟有实质影响，但不证明每一次历史超时都由此引起。见[HTTPS / UDP 超时调查](REQUEST_TIMEOUT_INVESTIGATION_2026-10-18.md)。
- **UDP 失效连接缓存**：写失败或短写后淘汰失效连接，下一次请求可创建新连接；不重放交付状态不明的报文，取消仍能中止阻塞。补充匿名 STUN 九阶段桥接诊断，保留日志上限。隔离回归在旧代码失败、修复后通过，但不能将全部历史 UDP 超时倒推为同一根因。见[桥接诊断与修复](BRIDGE_UDP_DIAGNOSTICS_2026-10-18.md)。
