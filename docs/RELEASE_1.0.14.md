# GoConnect 1.0.14（build 74）

修复“按名单代理”模式下，公网网站反复请求浏览器本地网络权限的问题。

- 名单模式停止返回会被浏览器判为局域网的虚拟 IPv6 地址，保留 IPv4 映射与按应用选择代理／原网络 DNS 的机制。
- 内网、本地域名、直连及专用解析域仍可返回真实 IPv6；出站可继续访问 IPv6-only 服务。全局模式保留代理 DoH 与真实 IPv6 解析。
- 保留浏览器对真实局域网请求的权限保护，不批量授权、不关闭安全保护。继承 1.0.13 的原生更新弹窗心跳与既有公司 socket 修复。

更新后请按“诊断”页提示升级本机网络服务，再正常重连。检查、下载和验签可保持 VPN；保存线路草稿并确认安装重启后，才正常断开。自动检查默认关闭，下载和安装由用户确认。

已完成团队签名构建、真实包内内核回归、Chrome 公网／真实内网权限对照、本机主线安装、名单与全局 DNS、AI API 传输、国内与内网请求，以及原生模态弹窗连接稳定性检查。独立 QA 从 build 73 实际下载、验签、安装并单实例重启到 74；篡改 feed、草稿保护和冷启动连接门禁检查通过。

名单模式的延迟解析区域对原始 AAAA 查询返回空记录；仅接受原始 AAAA 且不接受 IPv4 映射的专用客户端仍有限制。App 自带 DoH 和独立 DNS 查询按各自流量路径处理。公司副连接本轮未重新进行服务器认证；历史 AnyConnect UDP 仍为已接受的发布非阻断限制，未重新完成稳定性验收。

适用于 Apple Silicon / macOS 26.0 及以上。沿用团队 RX44JC39GB 的 Apple Development + Hardened Runtime，未采用 Developer ID 分发签名，未经过 Apple 公证。应用 ZIP 与完整更新源继续使用既有 Ed25519 签名、公钥及固定生产地址。
