## 修复目标

### 更新安装不得只等待旧的服务 busy 缓存

旧流程在连接中“检测环境”后可能缓存 `busy=true`；用户确认安装更新并正常断开后，安装等待循环不重新读取服务状态，最终错误阻挡安装。

实现：保留正常断开、草稿/订阅/节点测试/维护/主副连接及退出前门禁。显式安装准备时使旧空闲确认失效；本地主副连接正常停止后，在 20 秒总截止时间内串行读取固定 helper 的当前状态，单次最多等待 5 秒，真正 busy 时默认每秒重试，不按 100ms 循环反复创建进程。

只有可信的新 `ready && !busy` 或固定 helper 明确报告 `notInstalled && !busy` 才确认空闲。`needsUpdate`、`requiresAuthorization`、不可读等返回中的 `busy=false` 不是空闲证据；应先在诊断页正常维护/确认服务，再重试安装。不强制清零 busy，不因检查或下载更新而断开 VPN。generation 防止旧诊断读取覆盖较新的维护状态；取消/超时不采纳迟到的回复，并终止本次只读状态子进程，不终止已安装服务或 VPN。测试使用内存假状态及项目外临时假 helper，不接触生产服务。

### 名单 DNS 映射地址池在启动前检查冲突

旧名单模式使用 `198.18.0.0/16` 映射公网域名，但仅校验 TUN 接口保留地址。若已有更具体本地网络路由覆盖映射池，请求可能无法进入 TUN。

实现：配置和校验共同使用 `managedDNSFakeIPRange`，并统一按“有 managed DNS、名单模式、非 ProbeOnly”启用。纯前缀校验覆盖本机接口、既有 IPv4 路由、本地/Tailscale 保留路径、直连 IP 规则、公司网段，以及主 VPN/原物理/外层网关、原生默认/私有 DNS、公司网关/DNS 等已有控制端点；IPv4-mapped 控制地址归一化后比较。

复审补齐：冲突发现独立读取系统 IPv4 路由表，不复用仅保留私网的 DIRECT 路由列表。`198.18.42.0/24` 这类非 RFC1918 静态路由，以及其他隧道、接口、主机缓存、reject/blackhole 路由都纳入冲突判断；默认路由排除，DIRECT 优先级与本地网段发现规则不变。读取失败也在进入新会话前停止，未启用 fake-IP 的模式不增加这次路由读取。回归使用合成 Darwin 路由表，不向当前系统添加测试路由。

真实启动路径使用 `withValidatedTransparentAddresses` 包住创建新设备至 `connection.run` 的后续步骤。地址发现失败或检测到冲突即停止，不进入本次会话的 TUN、新增路由或 DNS 安装，不抢占、删除或自动改写已有网络。错误只包含池及来源类型，不打印用户具体地址。未使用名单 fake-IP 的全局模式和探测模式不额外占用该池，既有遗留会话恢复顺序及 TUN 地址校验保留。

这是启动前、已发现/已配置地址的冲突检测，不代表已全面覆盖连接后其他软件新增接口/路由的全部热变化。测试直接执行生产使用的启动 guard 和纯校验，不制造真实网段冲突，也不声称完成特权完整启动验收。

### 隔离 OTA 的空闲确认不读取正式服务

复审发现，新安装准备流程会查询服务，但原 UpdateQA 入口只隔离数据目录，没有替换真实服务状态源。现在由同一 `AppDelegate.makeStore` 工厂组装真实入口与回归测试；仅当 bundle ID 精确为 `com.willhsu.GoConnect.UpdateQA` 且 `GoConnectUpdateQAMode` 为布尔真时，注入不启动 helper 的隔离状态源。正式 bundle 仍使用固定 helper 和原有空闲核验，不读取偏好或环境变量来选择该例外。

QA 仍经正常安装准备、模拟连接退出、草稿和其他操作保护；从实际工厂创建的测试无需任何 Runtime/helper 即可完成准备，草稿仍在断开前阻止安装。QA 的模拟空闲只用于隔离更新机制验收，不代表正式服务已空闲，也不替代完整真实 OTA、已安装服务或系统网络验收。
